## Foundations already proven (use, do not rebuild)

- The sim is integer-only, 60 Hz and single-RNG. It is proven bit-exact vs
  the original only for Napa L1 (field 2400/2400, human 1431/1431) and the
  six police captures (parked 635, crashed 935, on-foot 605×2, city 456
  ticks), each from one RNG anchor. (Correction from review:) City AI RNG
  after tick 954, other courses and levels, and human control outside the
  1431-tick capture are still open, and cross-platform bit-identity is
  unproven until plan 34 Task 3's matrix. Do not treat these as settled.
- `RaceConfig`/`make_race_setup` (`src/race_setup.*`) is the single race
  factory every mode must go through (plan 26).
- `src/race_screen.cpp` owns the race shell; `src/frontend.cpp` owns menu
  flow; `src/mixer.*` owns audio (must never consume sim RNG).

## Landmines (from the plan; verified reading, no code yet)

- Task 2 is the hard one: the sim is player-centred (`riders_[0]`, camera
  distance, ring centre, traffic/police anchors, HUD-coupled state,
  `set_demo_hold`). The plan requires inventorying every such read,
  separating view from sim, then generalising to N humans with one human
  taking exactly the old path (goldens re-prove it).
- Task 3 budget: worst-case frame (16 re-simulated ticks + saves) ≤ 4 ms on
  the MANGMI AIR X; fallbacks ordered in the plan. Measure early.
- `third_party/` has no WebRTC/datachannel library yet; Task 4 adds one
  with its licence file (licence rule in 00-INDEX), plus the licences of its
  dependencies (libjuice, usrsctp, the TLS library) in `third_party/` and the
  user guide. Fuzz target required.
- Server holds no game data and runs no sim (rooms/roster/sealer/log only).
