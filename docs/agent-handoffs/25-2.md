## Deviation from the spec (Step 3) — pre-existing hang found and fixed

The spec's `Impl::loop()` waits on `generation != seen` whenever it wakes. When
`bands > workers` (the spec's own test: 4 bands on a 2-thread pool), a worker
that finishes its first band goes back to `wait(generation != seen)`, but no new
generation ever arrives, so remaining bands are never picked up and `run()` hangs
forever (confirmed: `timeout 10` → exit 124 on the spec-exact implementation).

Fix (same file, `Impl::loop`): only wait when the queue is empty; otherwise keep
draining:

```cpp
if (queue.empty()) {
    wake.wait(lock, [&] { return stop || generation != seen; });
    if (stop) return;
    seen = generation;
} else if (stop) {
    return;
}
if (!queue.empty()) { work = std::move(queue.back()); queue.pop_back(); }
```

This preserves the existing reuse protocol (`pending`/`generation`) and is
covered by the spec test (4 bands × {1,2,4} threads) plus a 20× repeat stress.

## Exception propagation (as specced)

- `Impl` gains `std::exception_ptr first_error`; `loop()` catches per-band
  exceptions (`catch (...)`) and records the first under lock.
- `RenderThreads::run` waits for `pending == 0`, then exchanges out
  `first_error`, unlocks, and rethrows. Pool stays usable afterwards.
- Added `#include <exception>` and `#include <utility>`.
