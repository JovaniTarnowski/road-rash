  jump 669→2392 (+1723) cannot come from `steer()`.
- The only writer that adds to `0x288` is the contact-knock tail (`0x004052c0`,
  `race.cpp` ~`contact()`): `add = (0x2d8 * 0x188 + sar-bias) >> 8`,
  clamped to ±`0x29c`. So the original took a contact knock at tick 208
  (`0x188 != 0`) and native did not (`0x188 == 0`).
- The `traction()` surface->curve rewrite was ruled out: native surface is 0
  at the tick (temporary `RR_TRACTION_TRACE`, reverted).
- Ablation: disabling `ai_overtake` moves the divergence to tick 60, so the
  overtake path is load-bearing for matching, not the bug.
- Native frozen grid at tick 207 (temporary print, reverted): rider 2 at
  (13824, 19200), rider 4 at (13312, 43264), bracketing the player
  (13733, 28123). Original node rows agree on positions (13824/13568/13312)
  but carry NO lateral keys in this golden era.
