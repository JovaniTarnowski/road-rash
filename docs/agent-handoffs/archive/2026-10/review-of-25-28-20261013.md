## Findings (most severe first)

1. **HIGH: career races ignore the bike bought in the shop** (`7f3b840`, plan 26 Task 3).
   The game sets `config.career = true; config.bike = career.state.bike`, but
   `load_race_assets` replaces `bike_index` with
   `level_bike[level + rider*5]` whenever `config.career` is true
   (race_setup.cpp:58-62). Before, the game used `career.state.bike`, which
   `buy_bike` changes (career.cpp:91-93). Physics and the dashboard (the `Hud` is
   built with `bike_index`) both use the default bike instead of the owned one.
   Plan 26 only covered quick races in its Review Focus 5, so the plan shares
   the blame.
   **Fix:** use the table bike only when no explicit bike is supplied, e.g. a
   new `RaceConfig::bike_from_table` defaulting to false, set true only by the
   oracle harness and the race_setup/race_soak sweeps. Their hashes must stay
   identical. **Test:** add a case to `race_setup_test` with `career=true`,
   `bike=<index different from the table default>`, asserting
   `assets.bike_index == config.bike`.
2. **LOW: a malformed `.CAR` now disables the whole course instead of only
   traffic.** `load_race_assets` throws on a bad CAR file, and the fallback
   (`optional_scene=true`) throws again for the same reason. `assets` then stays
   empty (or stale from the previous course), and `restart()` dereferences
   `assets.actors`/`assets.course`, a null-pointer crash. Imports are
   hash-verified, so this is unlikely. Fix: an `optional_traffic` flag like
   `optional_scene`, and make `restart()` refuse with a logged error when
   `!assets.course || !assets.actors`.
3. **DOC ACCURACY: "race ends at the original finish" is not yet true.**
   `bounds.finish_position_q8` is the route-end placeholder ("until plan 17
   Task 1 traces the exact nodes"), so `wiring().finish == 1` means only that
   the hook is attached. The same overstatement is in the 26-3 handoff, the
   `7f3b840` subject line and the original review text. Correct it in
   PROGRESS when the orchestrator records plan 26.
4. **LOW: two small behaviour changes in `race_action` versus the old loop**
   (`b50dac8`):
   - without a pause menu, Android Back (`SDLK_AC_BACK`) now toggles pause;
     before, it only paused;
   - while paused, finger MOTION/UP events now reach `touch.handle` (the caller
     forwards every `none`); before, they were dropped.
   Both only affect the no-menu or paused paths. The second is arguably better
   (no stuck finger). Either keep both and note them in the plan, or restore
   the old behaviour; just make the choice explicit.
5. **PROCESS: shared docs are behind.**
   - `docs/PROGRESS.md` and `docs/VERIFICATION.md` have no entries for plans
     25–28. AGENTS.md requires both, and the integrator owns them.
     Plan 26's intentional gameplay change in particular needs recording.
   - The `00-INDEX.md` rows for plans 25–31 were reverted.
   - Plans 29–31 and `REVIEW-ORCHESTRATION.md` are still untracked. Commit them
     (docs-only) so they can't be lost.
   - Plan 27 Task 1 has no handoff; the determinism evidence above can be cited
     in its place.
