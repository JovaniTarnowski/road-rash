## 1. Exact addresses (disassembly + decompiled export, read-only)

Insertion tail — `0x00437bb0` (disassembly `analysis/original-disassembly.txt:437bb0-437bd7`,
decompiled `analysis/decompiled/00437bb0.c:7-9`):

```
437bb0: mov al,[ecx+0xc0]
437bb8: or  al,0x04
437bbe: mov [ecx+0xc0],al        (intermediate store, bit3 still present)
437bc4: and al,0xF7              (-0x9, clears bit3 / 0x08)
437bc6: mov [ecx+0xc0],al        (final store)
437bcc: ... call 0x00438aa0      (scheduler sorted insert)
```

Net effect: `final = (orig | 4) & ~8`, i.e. `(flags & 0xF7) | 4`. Live bit 2 (4) set,
removed bit 3 (8) cleared. Note the double store: a tracer sampling between
`437bbe` and `437bc6` would see bit3 still set; only the second store is final.

Removal — `0x00437be0` (`analysis/decompiled/00437be0.c`, disassembly `437be0-437c03`):

```
c0 &= 0xFB   (clears live bit 2)
+0x10 = +0x0c = DAT_004b7ecc + 100   (parks scheduler words ~100 ticks in the future)
DAT_004977b8 = 1
```

So a removed node can never satisfy the outer `+0x10 == tick` gate until reinserted.

Template copy — `0x00438930` (`analysis/decompiled/00438930.c:17-24`):

```
*(byte *)(obj + 0x30) = *template;   // int-index +0x30 = byte +0xc0
obj[0x31] = template[1];             // +0xc4 type
obj[5] = template[8];                // +0x14 interval; obj[4] = tick - interval (+0x10), obj[3] = tick (+0x0c)
...
FUN_00437bb0(obj);                   // insertion tail runs at the END of every build
```

`0x004387a0` (`analysis/decompiled/004387a0.c`) is a pure wrapper: calls
`0x00438930`, then fills words `>= 0xec` plus physics/handler words. It writes no
`+0xc0` byte itself; composition flows `template -> 438930 -> 37bb0 tail`.

Scheduler tick-run — `0x00437e60` head (`analysis/decompiled/00437e60.c:11-13`):
`+0x10 = tick; +0x18 = tick - old`. The `0x004368f0` outer gate
(`analysis/decompiled/004368f0.c:21`, asm `436915-43692e`) is the conjunction
`obj[4] == DAT_004b7ecc && (c0 & 6) == 6`, i.e. **word `+0x10 == tick` AND flags**.
The candidate gate (`:31`, asm `436969-436973`) is `(c0 & 5) == 5`, evaluated
before any distance test (`436979` onward). `+0x10==tick` is a word comparison,
not c0 bit `0x10` — do not conflate them (see §3).

- Runtime hypothesis `c0 = 7`: `7 & 5 = 5` **pass**; `7 & 6 = 6` **pass**.

Therefore: **frame0 `bike_c0=4` must NOT be cited as the 893 runtime flag.**

branch for player pos30093 vs node4 pos30208) depends on runtime `+0xc0` bytes
