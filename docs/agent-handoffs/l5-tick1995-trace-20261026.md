## Lane-validity section: a real port gap, not this trigger

Reading the FULL 0x0044e710 decompile revealed an unconditional
lane-validity block (no obstacle gate) that native does NOT port: for
even kinds it checks whether the current lane fits the slice's lane
count and, if not, nudges the lane toward validity (with a
set-target-0/stop branch in one sub-path). Native `plan_speed` has ONLY
the obstacle-gated lane change, so this whole section is missing — a
genuine gap worth its own plan-16 task. It does NOT explain tick 1995:
a scratch probe (`leftlanes` at the car's sample 341) shows
leftlanes=2 while the car holds lane -2, so the gate
(`LEFTCOUNT < -lane`, i.e. 2 < 2) is false and the section is a no-op
for this exact state. (Caveat filed: the gate reads the slice at
native +0x50-equivalent; native has no +0x50 image, and the probe used
the car's current sample. If +0x50 ever points elsewhere, re-evaluate.)

## Why L5b can't replay (launch jitter, not a bug)

L5b differs from L5 in 36 frame-0 keys, ALL rider brain speed words
(rider.1/10 +0x19c/+0x1a4/+0x1bc/+0x1c0/+0x1c4...). This is the documented
run-varying launch jitter (`srand(time(NULL))` at WinMain; 0x004078f0
jitters personality level speeds before the race seed anchors RNG).
Everything else (positions, speeds, RNG stream, cars, nodes, ring) matches,
so L5b is a valid independent instance — but native's deterministic setup
models L5's jitter outcome, not L5b's, so L5b cannot serve as a replay
golden. It remains valuable as (a) proxy-extension validation (new keys
dump correctly), and (b) independent confirmation of the removal-run
signature with full internal state.
Narrowed further: the differing words match the `rand()%100` name-roll
outcome (0x00402e10: roll 42 → "Honest Phil" row set, 69 → "Veldaar",
else default rider names via 0x00402d60) selecting different personality
rows for riders 1 and 10 — same draw count (RNG stays in sync), different
rows. Verified the frontend session's proxy changes cannot cause this:
the menu watchdog thread is created only when RR_ORACLE_MENU is set
(gated), and the build change is link-flags only. The open question this
leaves for the integrator is how native's deterministic setup lands on
L5's jitter outcome (spare-levels path vs replay-harness seeding); it is
orthogonal to the car divergence and does not block it.

## Hydrated-mode probe (attempted, no conclusion — diagnostic-only as documented)

`RR_FIELD_IGNORE_CARS=1 RR_FIELD_CARS_FROM_GOLDEN=1` run to isolate the car:
diverges at frame 631 (tick 632), `rider.8.brain_194` (ai_target_x)
original -11008 vs native -15386. This does NOT indicate a second bug and
does NOT isolate the car:

- `load_cars` pairs golden slots (sorted by pool ADDRESS) with native cars
  (sorted by SERIAL). Pool realloc on spawn reshuffles addresses on either
  side independently, so the pairing can silently swap cars; the multiset
  compare in `cars()` is swap-proof, the hydration copy is not.
- Hydration copies only pos/lat/spd, leaving native motion words
  (m108/sign, signal latch, steer_error, lane) under golden positions —
  a mixed state the original never has, which AI planning reads
  (obstacle v108, lane gates). Any brain difference after that is
  artifactual by construction (`SIM_SCENARIOS.md`: hydrated runs "do not
  establish native traffic parity" and "never report identical").
- In the non-hydrated run every AI brain field matches through tick 1994,
  so AI planning inputs (including traffic as observed) are faithful up to
  the car tick.

No tree changes were made (env-var-only run). Do not use hydrated mode to
argue for or against the tick-1995 mechanism; it remains what the doc
says: a cadence diagnostic.
